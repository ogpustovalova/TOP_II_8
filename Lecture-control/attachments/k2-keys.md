# Рубежный срез К2: ключи для преподавателя

> Не включать этот файл в студенческий комплект контрольной.

Ответ может быть сформулирован иначе. Уровень по каждому критерию определяется
по полноте перечисленных элементов и рубрике.

## Вариант 1

### Часть А

1. Остаточный путь добавляет вход блока к преобразованию и создаёт короткий путь
   для сигнала и градиента, упрощая обучение глубоких сетей.
2. Max pooling выбирает максимальный локальный отклик, уменьшает разрешение и
   повышает устойчивость к малым сдвигам, но теряет точное положение и слабые
   признаки.
3. LSTM хранит hidden state и отдельное cell state с входным, забывающим и
   выходным гейтами; GRU объединяет память в hidden state и использует меньше
   гейтов.
4. KL приближает распределение латентных кодов к выбранному prior, делает
   пространство более регулярным и пригодным для генерации.

### Часть Б

1. После свёртки: **`32×32×32`**; после pooling: **`16×16×32`**.
   Параметры: `32×(3×3×3+1)=` **896**.
2. При одном bias на гейт: `4h(d+h+1)=4×32×(64+32+1)=` **12 416**.
   Формула PyTorch с двумя bias на гейт отличается; студент получает полный
   балл, если явно указал и последовательно применил библиотечную конвенцию.

### Часть В

Нужны фиксированные стратифицированные train/validation/test, выбор 20 объектов
только из train, одинаковая голова и преобразования, ImageNet-нормализация.
Сначала обучается голова frozen backbone, затем отдельная копия или сохранённое
состояние fine-tuning с малым lr. Выбор делается по validation, test используется
после выбора. Сравниваются accuracy, время и число обучаемых параметров. Риски:
переобучение, дисбаланс, утечка test, слишком большой lr и нестабильность seed.

## Вариант 2

### Часть А

1. Свёртка разделяет веса между позициями и использует локальную связность;
   полносвязный слой имеет отдельный вес для каждой пары вход–выход.
2. Заморозка сохраняет предобученные признаки и уменьшает число настраиваемых
   параметров на малой выборке. Малый lr при fine-tuning снижает риск разрушить
   полезные веса backbone и катастрофического забывания.
3. Токенизация выделяет единицы текста, морфология определяет формы и леммы,
   синтаксический анализ строит связи `head/dependency` между токенами.
4. AdamW отделяет weight decay от адаптивного шага по градиенту; обычное
   добавление L2 к loss проходит через адаптивное масштабирование Adam.

### Часть Б

1. `floor((64-5+2×2)/2)+1=32`; выход **`32×32×16`**. Параметры:
   `16×(3×5×5+1)=` **1 216**.
2. `3h(d+h+1)=3×64×(50+64+1)=` **22 080** параметров при одном bias на
   гейт. Библиотечная конвенция с двумя bias принимается при явном пояснении.

### Часть В

Есть переобучение и утечка словаря. Сначала выполняется стратифицированное
разбиение, затем словарь и все обучаемые преобразования строятся только по train;
validation выбирает архитектуру/hidden size, test используется один раз.
Regex, токенизация, PAD/OOV и длина должны совпадать для всех частей. LSTM, GRU и
1D-CNN обучаются с одинаковыми seed, бюджетом эпох и early stopping; сравниваются
validation/test accuracy, время и параметры. Уместны Dropout, уменьшение модели
и анализ ошибок.

## Вариант 3

### Часть А

1. Regex заменяет или выделяет шаблоны и возвращает нормализованный текст;
   морфологический анализ определяет формы/леммы токенов; синтаксический анализ
   возвращает дерево или таблицу связей `token — head — dependency`.
2. Репараметризация выносит случайность в `ε`, сохраняя дифференцируемость по
   параметрам `μ` и `σ`.
3. Scheduler меняет lr по времени или метрике, ускоряя начальное обучение и
   позволяя точнее донастраивать параметры позже.
4. Проверка save/load обнаруживает сохранение не того состояния, несовместимую
   конфигурацию или отличие предобработки и подтверждает воспроизводимость.

### Часть Б

1. `floor((28-3+2×1)/2)+1=14`; выход **`14×14×32`**. Параметры:
   `32×(1×3×3+1)=` **320**.
2. Общий слой: `10×8+8=88`; каждая голова: `8×2+2=18`; всего
   **124 параметра**. Для первой координаты KL-вклад 0; для второй выражение в
   скобках равно `-1`. `D_KL=-0,5×(-1)=` **0,5**.

### Часть В

Случайное перемешивание соседних окон перед разбиением создаёт временную утечку:
почти одинаковые участки ряда попадают в train и test. Требуется хронологическое
разбиение train→validation→test и статистики нормализации только по train. Окна
формируются после задания границ так, чтобы вся пара `(input, target)` оставалась
в одной части; при пересекающихся горизонтах вводится gap. Гиперпараметры
выбираются по validation. Наивный прогноз последним доступным или сезонным
значением считается в том же горизонте; test сравнивается один раз после выбора
модели. LSTM и GRU с `hidden_size=32/64` обучаются на одинаковых окнах, seed,
бюджете эпох и критерии early stopping; конфигурация выбирается по validation,
после чего выбранные модели однократно сравниваются на test по MAE и времени.

## Вариант 4

### Часть А

1. Self-attention на каждом шаге может напрямую взвешивать все позиции
   последовательности; RNN передаёт информацию через цепочку скрытых состояний
   и ограничен длиной пути градиента.
2. Масштаб стабилизирует скалярные произведения при большом \(d_k\), иначе
   softmax насыщается и градиенты затухают.
3. Feature extraction — замороженный backbone, обучается только голова;
   fine-tuning — разморозка части или всех слоёв с малым lr.
4. `ReduceLROnPlateau` снижает lr при отсутствии улучшения validation-метрики;
   `CosineAnnealingLR` меняет lr по заранее заданной траектории от эпохи, без
   опоры на метрику.

### Часть Б

1. После свёртки: **`16×16×16`**; после pooling: **`8×8×16`**. Параметры:
   `16×(3×3×8+1)=` **1 168**.
2. Матрица attention-весов имеет размер \(T×T=4×4\), то есть **16** скалярных
   значений (по одной строке softmax на каждый запрос).

### Часть В

Нарушения: test использован для выбора гиперпараметров LSTM; DistilBERT без
fine-tuning и без сопоставимого протокола обучения не сравнивается честно с
обученным LSTM; нет общего фиксированного train/validation/test и, возможно,
разной предобработки. Честная схема: один стратифицированный split; словарь и
токенизатор только по train; validation выбирает гиперпараметры обеих моделей;
для трансформера — либо frozen encoder + голова, либо fine-tuning с малым lr;
test — один раз после выбора; кроме accuracy — время, число обучаемых
параметров, анализ ошибок.

## Вариант 5

### Часть А

1. Разные фильтры извлекают разные признаки (грани, текстуры и т.д.).
2. Область входа, влияющая на выход; растёт с глубиной, stride, размером ядра,
   dilation.
3. Teacher forcing подставляет истинный предыдущий токен при обучении; на
   инференсе модель опирается на собственные предсказания.
4. Адаптивный шаг по координатам: 1-й момент — направление, 2-й — масштаб.

### Часть Б

1. Выход **`18×18×8`**; параметры `8×(3×3×16+1)=` **1 160**.
2. `4·20·(10+20+1)=` **2 480**.

### Часть В

Сдвиг домена (освещение). Аугментация яркости/шума, ночные кадры в train,
fine-tuning с малым lr, мониторинг дневной validation, не затирать дневной
набор.

## Вариант 6

### Часть А

1. GAP усредняет карту признаков, меньше параметров и меньше переобучение, чем
   flatten + большой Dense.
2. `1×1` сжимает/расширяет каналы, `3×3` работает в узком пространстве —
   экономия параметров.
3. Таблица векторных представлений токенов; инициализация случайная или из
   предобучения.
4. Weight decay регуляризует веса; уменьшение lr меняет шаг оптимизации.

### Часть Б

1. После conv **`32×32×16`**, после pool **`16×16×16`**; параметры
   `16×(5×5×1+1)=` **416**.
2. `3·16·(32+16+1)=` **2 352**.

### Часть В

Слишком большой lr разрушил pretrained веса. Frozen → постепенная разморозка,
lr на порядок меньше, чем у головы, discriminative lr.

## Вариант 7

### Часть А

1. Dilated: пропуски в ядре, больший receptive field без роста параметров.
2. Исключает padding из рекуррентного шага, считает только реальные длины.
3. Ошибку восстановления входа из латентного кода (MSE и др.).
4. Когда градиенты шумные / масштабы координат разные; Adam часто устойчивее на
   старте.

### Часть Б

1. `floor((14-3+2)/2)+1=7` → **`7×7×32`**; параметры `32×(3×3×32+1)=` **9 248**.
2. Две головы: `2×(16×4+4)=` **136**. При `μ=0`, `log σ²=0` слагаемое в KL
   для координаты **0**.

### Часть В

Аномалии в проде другого типа / порог по train-нормальным. Нужен holdout
аномалий, калибровка порога по validation, мониторинг drift.

## Вариант 8

### Часть А

1. Разные head могут смотреть на разные типы связей (синтаксис, позиция).
2. Без позиции attention перестановочно-инвариантен; PE задаёт порядок.
3. BN — по batch и spatial; LN — по признакам одного объекта.
4. Плавный рост lr в начале стабилизирует обучение больших моделей.

### Часть Б

1. **`8×8×64`**; параметры `64×(3×3×64+1)=` **36 928**.
2. **`8×8`**.

### Часть В

Одинаковый split, бюджет вычислений, тюнинг lr/эпох для обеих, validation до
test, несколько seed, отчёт параметров и latency — иначе сравнение некорректно.

## Вариант 9

### Часть А

1. Skip добавляет вход блока к выходу; attention взвешивает все позиции.
2. Экономия памяти: пересчёт активаций вместо хранения всех.
3. Сжатое представление входа в меньшей размерности.
4. Периодический «перезапуск» lr помогает выйти из острых минимумов.

### Часть Б

1. `floor((64-3+2)/2)+1=32` → **`32×32×32`**; параметры `32×(3×3×3+1)=` **896**.
2. **`5000×64=320 000`**.

### Часть В

Хронологический split / по сезонам, признаки календаря осторожно (утечка),
rolling validation, baseline сезонности.

## Вариант 10

### Часть А

1. Cross-attention: queries из одного потока (decoder), keys/values из другого
   (encoder); self — всё из одного.
2. Убирает дублирующие боксы с высоким IoU, оставляя лучший score.
3. Генератор схлопывается к узкому набору образцов.
4. Иначе сравнивают плохой lr одного метода с удачным другого.

### Часть Б

1. После второй: **`28×28×32`**; параметры второй: `32×(3×3×16+1)=` **4 640**.
2. **`d_k=16`**.

### Часть В

Таблица: validation F1, p95 latency на CPU, RSS памяти, стоимость доразметки,
частота переобучения; выбрать минимально достаточную модель под SLO, не «самую
модную».
